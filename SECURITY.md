# Security Policy

## Supported version

Security fixes are made against the current `main` branch and the current production deployment of [solarcomplaint.com](https://solarcomplaint.com).

## Report a vulnerability privately

Do **not** open a public issue, pull request, or discussion for a suspected vulnerability.

Use the private form at [solarcomplaint.com](https://solarcomplaint.com/#questions) and begin the message with **“Security report.”** Include:

- A concise description of the issue
- The affected page, endpoint, or component
- Steps to reproduce it safely
- The potential impact
- Any suggested mitigation, if known

Do not include unnecessary personal information. Do not publicly disclose the issue while it is being reviewed.

## What belongs here

Examples include:

- Exposed credentials or secrets
- Unauthorized access to private accounts, questions, or data
- Authentication, authorization, or session flaws
- Cross-site scripting, injection, or other security defects
- A way to bypass a security control

This policy does not cover source corrections, individual solar situations, Code of Conduct reports, or general site feedback.

## What to expect

Reports will be reviewed privately. If the issue is confirmed, the project will work to address it before public disclosure. The reporter’s information will be handled as privately as the circumstances allow.

## Safe-harbor expectations

Do not access data that does not belong to you, disrupt the service, perform denial-of-service testing, or publicly disclose a suspected vulnerability before it has been reviewed. Good-faith reports that follow these limits are welcome.
